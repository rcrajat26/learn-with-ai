Pattern extraction. Everything here is written to survive without the stock

## 1. Pattern

**Family:** *Single forward pass with a running prefix aggregate.* Also called
prefix-extremum scan, or one-dimensional DP whose state collapses to a scalar.
The Kadane family is the same machine with a different aggregate.

**Trigger:**

> **if** the answer is the best over all *ordered* pairs `(i, j)` with `i < j`,
> **and** the score of a pair separates into `f(j)` combined with an aggregate
> over `prices[0..j-1]` that does not depend on `j`,
> **→ reach for a single left-to-right pass carrying that aggregate as one scalar.**

Sub-triggers that should fire the same reflex:

| Phrasing in the statement | What it means |
|---|---|
| "a different day **in the future**" / "must buy before you sell" | ordered pair, `i < j`; the array is **not** a multiset |
| "maximum difference `A[j] - A[i]` with `i < j`" | this pattern, verbatim |
| "maximum/minimum over all subarrays" with an additive score | same machine, aggregate = running best-ending-here |
| "single transaction" / "at most one operation" | the state is a scalar, not a table |
| `n ≤ 10^5` and the obvious answer is `O(n²)` | the `O(n²)` is a triangular double loop; one of the two loops is recomputable incrementally |

**Anti-trigger:** if the pair is *unordered* (`i` and `j` interchangeable), you
have a max−min problem and order is irrelevant — sort or scan for global
extrema. That difference is exactly what broke attempt 1.

## 2. The transferable trick

> **Freeze the later endpoint, and the earlier endpoint stops being a search.**

The brute force searches for two things at once. Do not. Commit to `j` — the
right-hand endpoint — and ask: given `j` is fixed, what is the best legal `i`?
For a difference score the answer is not a search at all, it is a single number:
the minimum of everything strictly left of `j`. So the inner loop collapses to a
lookup, and the lookup is a *prefix aggregate*, and a prefix aggregate over a
left-to-right sweep costs `O(1)` per step to maintain.

The generalisation, worth memorising in this form:

```
answer = max over j of  score(j, best_partner_for_j)
best_partner_for_j = some aggregate of the prefix [0 .. j-1]
```

If that aggregate is *maintainable* — min, max, sum, count, running best — the
whole problem is one pass and `O(1)` space. If it is not maintainable (e.g. it
needs "the minimum in the last `W` elements"), you keep the frame and upgrade
the container: monotonic deque, heap, or a prefix array. **The frame survives
even when the scalar does not.** That is why the frame is the thing to learn.

Corollary on the converging two-pointer: converging pointers are for problems
where a *sortedness or symmetry* property lets you prove one side can be
discarded. An unsorted array with an order constraint gives you no such proof,
so `i` and `j` walking toward each other visit a shrinking set of pairs and
provably miss the ones where both endpoints live in the same half. There is no
patch. Recognising "this frame has no discard proof, abandon it" is a skill in
itself.

## 3. The invariant template

```java
public int solve(int[] a) {
    if (a.length == 0) return IDENTITY_ANSWER;

    int agg  = IDENTITY_AGGREGATE;   // e.g. Integer.MAX_VALUE for a running min
    int best = IDENTITY_ANSWER;      // e.g. 0 when "do nothing" is legal

    for (int x : a) {
        // INVARIANT, true on entry to every iteration for element at index i:
        //   agg  == AGGREGATE of a[0 .. i-1]     <-- range EXCLUDES i
        //   best == the answer for a[0 .. i-1]
        //
        // Order of the two updates below is the correctness argument.
        // Fold x into `agg` FIRST  => i is allowed to pair with itself.
        // Score x against `agg` FIRST => i must pair with a strictly earlier index.
        // Pick the one the problem's ordering rule demands, and comment why.

        agg  = COMBINE(agg, x);              // <-- or swap these
        best = Math.max(best, SCORE(x, agg));// <-- two lines
    }
    return best;
}
```

Placeholders for the three instantiations you now know:

| | `agg` | `COMBINE` | `SCORE(x, agg)` | order |
|---|---|---|---|---|
| Max `A[j] − A[i]`, `i ≤ j` | running min | `min(agg, x)` | `x − agg` | combine first |
| Max `A[j] − A[i]`, `i < j` strictly | running min | `min(agg, x)` | `x − agg` | **score first** |
| Kadane, max subarray sum | best sum ending here | `max(x, agg + x)` | `agg` | combine first |

Note rows 1 and 2 differ only by swapping two lines, and both compile, and both
return 5 on `[7,1,5,3,6,4]`. That is the trap; see § 5.

## 4. Recognition drill

For each, decide: does the prefix-extremum single-pass pattern fire?

1. Given an integer array, return the maximum of `A[j] − A[i]` over all `i < j`,
   or 0 if no such pair is positive.
2. Given an integer array, return the difference between the largest and
   smallest element.
3. Given an array of daily temperatures, for each day return how many days until
   a warmer one.
4. Given an integer array, return the maximum sum of any non-empty contiguous
   subarray.
5. Given an array, return the number of pairs `i < j` with `A[i] > A[j]`.
6. Given an array and integer `k`, return the maximum of `A[j] − A[i]` over all
   `i < j` with `j − i >= k`.
7. Given an array of prices, return the maximum profit if you may complete **as
   many** transactions as you like (buy and sell repeatedly, never holding two).
8. Given an array, return the maximum product of any contiguous subarray.

<details>
<summary>Answer key</summary>

1. **Fires.** This is the question itself, restated cold.
2. **Does not fire** — and this is the near-miss that matters most. No order
   constraint, so it is a pure multiset question: one pass for global min and
   global max, order irrelevant, `[2,1]` and `[1,2]` give the same answer. This
   is precisely the problem attempt 1 accidentally solved. If you cannot say in
   one sentence why 1 and 2 are different problems, re-read § 2.
3. **Does not fire.** The partner is "the next element satisfying a predicate",
   not an aggregate of the prefix — a scalar cannot represent it. Monotonic
   stack, and the sweep is right-to-left or uses a pending stack.
4. **Fires.** Kadane. Same skeleton, `agg` is best-sum-ending-here.
5. **Does not fire** as a scalar. Counting inversions needs an order-statistic
   structure (BIT / merge sort). The frame "fix `j`, ask about the prefix"
   still applies, but the prefix query is a rank, not an extremum — this is the
   canonical "upgrade the container, keep the frame" case.
6. **Fires, with a lag.** Same pass, but `agg` must be the min of `A[0..j−k]`,
   so you fold in element `j−k` at step `j` instead of element `j`. One-line
   change to the template; the invariant range changes from `0..i−1` to `0..i−k`.
7. **Does not fire** in this form — and it looks like it should, which is the
   point. The answer is the sum of all positive consecutive differences; there
   is no single held aggregate, because every local rise is independently
   harvestable. Greedy one-pass, yes; *prefix-extremum*, no.
8. **Near-miss.** One pass, but the scalar is not sufficient: negatives flip
   sign, so you must carry **two** values (best and worst product ending here).
   The frame holds; the state is a pair, not a scalar. Good reminder that
   "collapses to `O(1)` space" does not mean "collapses to one variable".

Score 6+/8 and the trigger is internalised. Miss #2 or #7 and re-read § 1.

</details>

## 5. Failure modes for this pattern

1. **Wrong update order in the loop body.** The single most common bug in the
   whole family, and it is invisible to casual testing because both orders agree
   on any input where the optimal buy is strictly before the optimal sell — i.e.
   almost every hand-picked example. Distinguishing input: a strictly decreasing
   array such as `[7,6,4,3,1]`. Score-first yields a negative running best;
   combine-first yields `0`. Decide the order from the invariant range
   (`0..i−1` vs `0..i`), never from "it passed the samples".

2. **Seeding `best` at `MIN_VALUE` when the identity is `0`.** Safe only if the
   score is provably non-negative on the first iteration, which is itself a
   consequence of the update order. Two smells that cancel is not a design.
   Seed `best = 0` when "do nothing" is a legal answer, and `MIN_VALUE` only
   when the problem forces a non-empty selection.

3. **Seeding `agg` at `0` instead of `MAX_VALUE`.** Fatal on all-positive input
   for a running min: `agg` never updates and the answer becomes `max(A)`.
   The identity element for `min` is `+∞`, not zero.

4. **Off-by-one in the prefix range.** `0..i−1` (strict `i < j`) versus `0..i`
   (permits `i == j`). Read the statement for the word "different" or "another".
   Same day allowed → combine first. Same day forbidden → score first, and then
   you must seed and floor `best` correctly, because a negative is now reachable.

5. **Reaching for converging two pointers because the problem has two indices.**
   Two indices in the answer does not mean two pointers in the loop. Ask for the
   discard proof: "when I move the left pointer, what have I proved about every
   pair it was still eligible for?" No proof, no converging scan.

6. **Overflow when the score is a sum rather than a difference.** `int` is fine
   here (`|A[i]| ≤ 10^4`, `n ≤ 10^5`, difference bounded by `10^4`), but the same
   skeleton on a max-subarray-sum problem with `10^5` elements of `10^9` needs
   `long`. Check the bound on the *score*, not on the elements.

7. **Empty-input handling written after the loop instead of before it.** With
   `best` seeded to the identity and a for-each loop, `n == 0` falls out for
   free. With `MIN_VALUE` seeding it returns garbage. Another argument for
   correct identities.

## 6. Personal error log for this question

Drawn from what actually happened, quoted.

### Attempt 1 — the frame error

- **Quoted:** *"I will try running two pointers one from left and another from
  right… The left pointer will check if the current element is less than the
  previous element… The right pointer will check if the current element is
  greater than the previous element."*
  This is failure mode #5. Two indices in the answer triggered two pointers in
  the loop, with no discard argument. The algorithm computed something close to
  `max(right half) − min(left half)`, which is neither the ordered-pair answer
  nor the multiset answer.

- **Quoted:** *"The J never got to reach 2nd index. We must allow i and j both
  look through all the values."*
  The diagnosis on `[3,2,6,5,0,3]` was **correct and self-generated** — that is
  a genuine strength. But the conclusion drawn was "widen the scan", i.e. patch
  the frame, when the correct conclusion was "the frame is unsalvageable". The
  gap is not analysis, it is being willing to discard.

- **Quoted:** *"I failed initially with placing `i++` and `j--` condition within
  if block and the time ran out."*
  An infinite loop caused by conditional advancement. Secondary lesson: in any
  pointer loop, prove that **every** path through the body advances at least one
  pointer, before you run it.

- **Not written down at all:** the sentence "does my answer depend on order or
  only on the multiset?" It was Hint 1, then item 1 of the pass-2 checklist, and
  it never appeared. That one sentence is the entire diagnosis of attempt 1 and
  would have taken ten seconds.

### Attempt 2 — the explanation error

- **Quoted:** *"We track the local minimum and compare it with next numbers till
  we see next minimum. However, I'm not aware what's the pattern."*
  The code was `CORRECT & OPTIMAL`; the understanding was absent, and the
  terminology was wrong — it is a *running prefix minimum*, monotone
  non-increasing, not a "local minimum". Getting the right code from a wrong
  mental model is the most dangerous outcome in the whole exercise, because it
  does not feel like a failure.

- **Quoted:** `int mx = Integer.MIN_VALUE; … return mx;`
  Failure mode #2. Correct only because the min was folded in before scoring.
  One line-swap away from returning `Integer.MIN_VALUE`-adjacent garbage on
  `[7,6,4,3,1]`. The code was right by accident on this axis, and an accident is
  not repeatable under interview pressure.

- **Checklist hit rate 1.5 / 8**, and the distribution is the finding: both hits
  were *code* items; all six misses were *communication or verification* items —
  complexity (asked twice, delivered zero times across two attempts), invariant,
  bottleneck sentence, pre-submission self-test.

### The one habit to change

Not an algorithm skill. **Complexity and invariant were requested explicitly,
twice each, and produced zero times.** The fix is mechanical and should be
applied to every future question in this repo before submitting:

1. One line: `Time O(?) because …, Space O(?) because …`.
2. One comment on the loop: what is true of the variables on entry.
3. One table: the given examples plus one adversarial input, hand-traced,
   *before* the judge sees the code.

Testing after rejection (attempt 1) instead of before submission (attempt 2's
missing item 8) is the same habit failing at both ends.

## 7. Adjacent patterns

| Confused with | Distinguishing question |
|---|---|
| **Global max − global min** | Does the answer change if I reverse the array? If no, order is irrelevant and this is a multiset problem, not this pattern. |
| **Converging two pointers** | Is the array sorted, or is there a symmetry that proves one side can be discarded? No proof → not converging pointers. |
| **Sliding window** | Is there a length or budget constraint on the span `j − i`? If unconstrained, you want a prefix aggregate, not a window. If constrained, you want a window and probably a monotonic deque. |
| **Monotonic stack** | Is the partner "the *nearest* element satisfying a predicate" rather than "the *best* element in the prefix"? Nearest → stack. Best → scalar. |
| **Kadane** | Same machine. The distinction is only what `agg` means: prefix extremum of *values* versus best score *ending here*. Difference-of-pairs converts to Kadane on the adjacent-difference array; they are literally the same problem. |
| **Full DP table** | Is there more than one transaction, or a state (holding / not holding / cooldown)? More than a scalar of state → array or fixed set of variables per state, and the collapse to `O(1)` space no longer happens automatically. |
| **Prefix/suffix two-array scan** | Does the answer need an aggregate from *both* sides of a split point? Then you cannot do it in one pass with one scalar — precompute a suffix array, or run two passes. |
