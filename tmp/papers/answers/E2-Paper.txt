Q1. What is the time complexity of this snippet, and why?

for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        sum += a[i] + a[j];
Follow-up: and if the inner loop started at j = i?
- for every outer loop inner loop runs n time each hence O(n2)
- when j=i it becomes triangular from square so time complexity is O(n2)

Section 2 — Java Core
Q3. Checked vs unchecked exceptions: what's the compiler-level difference, and name one standard example of each.
- Checked exception is known at compile time hence compiler is aware that an exception can occur, like FileNotFoundException if the given file was not present in the folder
- Unchecked exception occur at runtime so compiler isnt aware of it like IndexOutOfBoundException if we try access an element not in the given array

Q4. Interface vs abstract class — two differences, and one situation where you must use an abstract class.

- For high level blueprints we'd use Interface, while for partial implementations we'd use abstract classes

Section 6 — Networking & OS
Q11. What do the status-code classes 2xx, 3xx, 4xx, 5xx each mean? Whose "fault" is a 4xx vs a 5xx?
- 2xx is success code, created, got response etc
- 3xx is redirect code, moved to new location, permanently moved etc
- 4xx is client side error code, such as requested resource not found, not having privilege (not authorized), not authenticated
- 5xx is server side error code, such as gateway timeout
- 4xx is clients fault while 5xx is server's fault.
--------------
Q12. What is an IP address and what is a port? Why does a machine with one IP need ports at all?
- IP address is a internet address assigned to server, if public it'll be unique making server discoverable on internet, port is an open (or closed) connection on which the client connects.
- IP is machine level and Port is application level a web application connects on one port 80, while same machine can be accessed via SSH on port 22. thus enabling a single machine to serve multiple applications

Q13. GET vs POST: two differences beyond "GET reads, POST writes" (think: caching, body, idempotency, URL visibility).

- POST used for writes has no significant difference off caching, body is generally needed to share the data which needs to be stored, is non-idempotent.

Section 8 — Messaging & Caching
Q15. What does TTL mean on a cache entry? What happens on a read after the TTL expires, and why is that usually acceptable?
- TTL is a amount of time we set for a cached entry to be valid, once TTL has expired a cache hits the original source (db) to get the latest value. A cached value can occasionally get updated to a new value hence its acceptable to hit the source occasionally however the TTL value must be optimally set as a very small value cam burden the DB defeating the purpose of cache, a very high value can pose risk of stale value getting delivered.
