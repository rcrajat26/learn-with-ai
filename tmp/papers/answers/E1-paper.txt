Section 4 — Spring & JPA
Q7. In one sentence each: what problem does dependency injection solve, and what does the @Autowired/constructor-injection mechanism actually do?
DI solves the problem of inverting the control of bean creation to factory and supplying wherever needed, there by removing the tight coupling and enhancing testability and flexibility of the code. The @Autowired/Constructor Injection figures out all the dependencies of a given bean before creating that bean, and goes on to create the sub-beans once all the sub-beans are ready goes on to create the actual bean, meaning at the time of initialization itself the bean is created with all the dependencies intact.

Section 9 — Testing & Craft
Q17. Unit test vs integration test — define each. Which is usually faster and why?
- Unit test does test a piece of code mocking all the external dependencies. It doesnt make any HTTP/DB calls
- Integration test tests the code by bringing actual dependencies the in the mocked format making HTTP/DB calls to a mocked entity.
- Unit test much faster as it doesnt need to depend on any external system and is as good as running the application itself.
-------------
Q18. What is a mock and why do tests use them? Give one example of a dependency you would mock.
- A mock is piece of code that mimics behaviour of an external system like DB, which returns the same entity with created ID upon saving, or throw an exception when a user is not present. We can mimic this behaviour by conditionally returning a user or exception.
