# Distributed Tracing Flow: Payments Gateway → PSP Integration Service

## Quick Answers to Your Questions

### 1. **Why Fetch trace_id and span_id? Are We Not Generating Them?**

**Answer:** OpenTelemetry GENERATES them, not you. Here's the hierarchy:

```
OpenTelemetry (external library/agent)
    ↓
Generates SpanContext (trace_id, span_id, trace flags, etc.)
    ↓
Your code FETCHES them from current Span
    ↓
Your code puts them into logging context (MDC) for correlation
```

**Why this design?**
- OpenTelemetry auto-generates unique IDs that follow W3C Trace Context standard
- These IDs are globally unique and traceable across all services
- You simply retrieve and log them to correlate logs with traces

---

### 2. **How Same trace_id is Sent to Next Application**

The trace_id is propagated via **HTTP headers** using the **W3C Trace Context standard**:

```
Client (Payments Gateway)
    ↓ Creates HTTP Request to PSP Service
    ↓ OpenTelemetry Feign Interceptor adds headers:
       - traceparent: 00-[TRACE_ID]-[SPAN_ID]-[FLAGS]
       - X-REQUEST-ID: [TRACE_ID]
    ↓
HTTP Network
    ↓
Server (PSP Integration Service)
    ↓ Receives request with tracing headers
    ↓ OpenTelemetry reads headers
    ↓ Creates new Span under SAME trace_id
    ↓ Logs are correlated using same trace_id
```

---

### 3. **What Exactly OpenTelemetry Does While Auto-Populating MDC**

OpenTelemetry has built-in integration with SLF4J's MDC:

```
OpenTelemetry Auto-Instrumentation (Spring integration)
    ↓
Detects SLF4J on classpath
    ↓
Automatically registers MDC context propagator
    ↓
When span is active:
   - MDC.put("trace_id", "abc123...")
   - MDC.put("span_id", "xyz789...")
   - MDC.put("trace_flags", "01")
    ↓
When you log via SLF4J:
   - Logback's %X{trace_id} retrieves from MDC
   - No code needed from you
```

**Key Point:** This happens automatically—you don't call MDC.put(). OpenTelemetry does it via:
- `io.opentelemetry.instrumentation:opentelemetry-instrumentation-logging-mdc`
- Spring Cloud OpenTelemetry auto-configuration

### 4. **What Exactly Happens in Log File Writing - %X Meaning**

#### Logback Pattern Syntax
```
%X{trace_id}  = Read trace_id from MDC dictionary
%X{span_id}   = Read span_id from MDC dictionary
```

#### Log File Output Flow

```
Log statement in code:
   log.info("Processing payment");

Logback encoder processes pattern:
   <pattern>
      %date severity=%-5level logger="%logger{15}" 
      thread="%thread" traceId="%X{trace_id}" spanId="%X{span_id}" 
      msg="%msg"%n
   </pattern>

Variable Resolution:
   %date          → 2025-09-05 14:32:15.123
   %-5level       → INFO 
   %logger{15}    → PaymentService (truncated to 15 chars)
   %thread        → http-nio-8080-exec-1
   %X{trace_id}   → MDC.get("trace_id") → "a1b2c3d4e5f6g7h8"
   %X{span_id}    → MDC.get("span_id")  → "x1y2z3a4b5c6"
   %msg           → "Processing payment"

Final Log Line:
   2025-09-05 14:32:15.123 severity=INFO logger="PaymentService" 
   thread="http-nio-8080-exec-1" traceId="a1b2c3d4e5f6g7h8" 
   spanId="x1y2z3a4b5c6" msg="Processing payment"
```

#### If trace_id Not in MDC
```
If %X{key} doesn't exist in MDC:
   → Output is empty (no error)
   → Log line shows: traceId=""
   → Indicates no active span/tracing at that point
```

## Complete End-to-End Flow: Payments Gateway → PSP Service

### **Phase 1: Request Arrives at Payments Gateway**

```
1. Client sends HTTP request to Payments Gateway
   POST /payments
   
2. TracingSupportFilter (OncePerRequestFilter) intercepts
   
3. OpenTelemetry auto-creates span:
   Span current = Span.current()
   SpanContext spanContext = current.getSpanContext()
   
4. Extract IDs:
   traceId = "a1b2c3d4e5f6g7h8"  (unique, generated by OT)
   spanId = "x1y2z3a4b5c6"       (spans are hierarchical)
   
5. Store in request attributes (for later logging):
   request.setAttribute("callerReqId", "a1b2c3d4e5f6g7h8")
   request.setAttribute("reqId", "x1y2z3a4b5c6")
   
6. OpenTelemetry auto-populates MDC:
   MDC.put("trace_id", "a1b2c3d4e5f6g7h8")
   MDC.put("span_id", "x1y2z3a4b5c6")
   
7. Payments Gateway business logic runs:
   log.info("Acquiring lock for account");  // auto-includes trace_id in MDC
   
8. Log line written to file:
   2025-09-05 14:32:15.123 severity=INFO logger="LockService" 
   thread="http-nio-8080-exec-1" 
   traceId="a1b2c3d4e5f6g7h8"       ← Same trace_id (from MDC via %X)
   spanId="x1y2z3a4b5c6" 
   msg="Acquiring lock for account"
```

### **Phase 2: Payments Gateway Acquires Lock**

```
9. Lock acquired on account for this transaction
   log.info("Lock acquired, proceeding to PSP");
   
   Output:
   traceId="a1b2c3d4e5f6g7h8"  (SAME trace_id)
   spanId="x1y2z3a4b5c6"       (same span while lock held)
```

### **Phase 3: Payments Gateway Calls PSP Integration Service**

```
10. SignatureVerificationService calls PspIntegrationServiceApi.verify()

11. FeignClient makes HTTP request to PSP service:
    POST http://psp-integration-service/security/webhooks/verifyEvent
    
12. OpenTelemetry Feign Interceptor auto-adds tracing headers:
    Headers added automatically:
    - traceparent: 00-a1b2c3d4e5f6g7h8-[NEW_SPAN_ID]-01
    - X-REQUEST-ID: a1b2c3d4e5f6g7h8
    - tracestate: ...
    
    (Note: trace_id stays SAME, but spanId is new for this hop)

13. HTTP request sent over network with headers:
    POST http://psp-integration-service/security/webhooks/verifyEvent
    traceparent: 00-a1b2c3d4e5f6g7h8-n9o8p7q6r5s4-01
    X-REQUEST-ID: a1b2c3d4e5f6g7h8
    Authorization: Bearer [JWT_TOKEN]  (added by ServiceTokenInjector)
    
    Body:
    {
      "psp": "stripe",
      "payload": "{...webhook payload...}",
      "headers": {...}
    }
```

### **Phase 4: PSP Integration Service Receives Request**

```
14. PSP service receives HTTP request with tracing headers

15. OpenTelemetry auto-reads traceparent header:
    - Extracts SAME trace_id: a1b2c3d4e5f6g7h8
    - Extracts parent span_id: x1y2z3a4b5c6
    - Creates NEW child span_id: p7q6r5s4t3u2 (for PSP service processing)

16. PSP TracingSupportFilter runs:
    SpanContext spanContext = Span.current().getSpanContext()
    traceId = "a1b2c3d4e5f6g7h8"  (SAME - propagated from header)
    spanId = "p7q6r5s4t3u2"       (NEW - this service's span)

17. OpenTelemetry auto-populates PSP service's MDC:
    MDC.put("trace_id", "a1b2c3d4e5f6g7h8")  ← SAME trace_id!
    MDC.put("span_id", "p7q6r5s4t3u2")      ← NEW span for PSP

18. PSP business logic runs with logging:
    log.info("Verifying webhook signature");
    
    Output:
    2025-09-05 14:32:15.234 severity=INFO logger="SignatureVerifier" 
    traceId="a1b2c3d4e5f6g7h8"     ← CORRELATED: same trace_id
    spanId="p7q6r5s4t3u2" 
    msg="Verifying webhook signature"
    
19. PSP service completes:
    return "valid";
    
    Response headers include:
    X-REQUEST-ID: a1b2c3d4e5f6g7h8  (trace_id in response)

20. PSP service writes response log:
    log.info("Webhook signature verified, returning result");
    
    traceId="a1b2c3d4e5f6g7h8"  ← CORRELATED
    spanId="p7q6r5s4t3u2"
```

### **Phase 5: Payments Gateway Receives Response**

```
21. Payments Gateway receives response from PSP service
    Response headers include: X-REQUEST-ID: a1b2c3d4e5f6g7h8

22. Payments Gateway releases lock:
    log.info("PSP verification complete, releasing lock");
    
    Output:
    traceId="a1b2c3d4e5f6g7h8"  ← SAME trace_id (still in MDC)
    spanId="x1y2z3a4b5c6"       ← Back to gateway's span

23. Payments Gateway returns response to client:
    HTTP 200 OK
    X-REQUEST-ID: a1b2c3d4e5f6g7h8  (trace_id in response header)
```

## How It All Works Together

### **Auto-Generation (OpenTelemetry)**
```
Java Agent / Spring Boot Starter auto-instruments:
├─ servlet-api (creates spans for HTTP requests)
├─ http-url-connection (for outgoing HTTP calls)
├─ feign (automatically adds W3C headers to Feign requests)
└─ logback (auto-populates MDC from active span)
```

### **Header Propagation (W3C Standard)**
```
W3C Trace Context (RFC 8487):
  traceparent: 00-<TRACE_ID>-<SPAN_ID>-<FLAGS>
  Example: 00-a1b2c3d4e5f6g7h8-n9o8p7q6r5s4-01
  
  00           = Version
  a1b2c3d4...  = Trace ID (128-bit, hex) ← SAME across all services
  n9o8p7q6...  = Span ID (64-bit, hex)   ← NEW for each service hop
  01           = Flags (sampled=1, recorded=1)
```

### **MDC Auto-Population (SLF4J Integration)**
```
Spring Cloud OpenTelemetry dependency:
  spring-cloud-starter-sleuth-otel
  ↓
Provides:
  - BaggageManager
  - LoggingContextInjector (auto-populates MDC)
  
When span is active:
  MDC.put("trace_id", span.getTraceId())
  MDC.put("span_id", span.getSpanId())
  
When logging:
  %X{trace_id} → looks up MDC.get("trace_id")
```

## Key Takeaways

| Concept | Who Does It | When | Why |
|---------|-----------|------|-----|
| **Generate trace_id** | OpenTelemetry agent | Request arrives | Unique identifier for entire flow |
| **Fetch trace_id** | Your code (TracingSupportFilter) | Early in filter chain | To access it for response headers |
| **Put in MDC** | OpenTelemetry (automatic) | When span becomes active | Makes it available to logging |
| **Log with %X** | Logback encoder | Each log statement | Reads from MDC, includes in output |
| **Send to next service** | OpenTelemetry Feign interceptor | Making HTTP request | Propagates via W3C traceparent header |
| **Receive at next service** | OpenTelemetry servlet instrumentation | Request arrives | Reads traceparent header, creates child span |

## Debugging Tips

### How to Find All Logs for One Transaction
```bash
# Get trace_id from any log line
grep "some-error-message" payments-gateway.log
# Output: traceId=a1b2c3d4e5f6g7h8

# Find all logs in that transaction across all services
grep "traceId=a1b2c3d4e5f6g7h8" *.log | sort -t: -k2,2

# Result: Complete flow across payments-gateway AND psp-integration-service
```

### If trace_id is Missing from Logs
```
Possible causes:
1. OpenTelemetry not initialized (check spring beans)
2. Span not active at logging point (check filter order)
3. %X{trace_id} not in logback pattern (check payments-gateway-logback.xml)
4. MDC not populated (check spring-cloud-starter-sleuth-otel dependency)
```

### Verify Headers Sent to PSP Service
```java
// In ServiceTokenInjector, RequestInterceptor.apply():
public void apply(RequestTemplate requestTemplate) {
    // OpenTelemetry automatically adds:
    // - traceparent header
    // - tracestate header
    // You add:
    requestTemplate.header("X-SECURITY-TOKEN", token);
    requestTemplate.header("Authorization", "Bearer " + token);
}
```
