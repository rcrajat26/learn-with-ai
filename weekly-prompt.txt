STRUCTURE (fixed — every week's file must follow this)
────────────────────────────────────────────────────────────────────────────

1. Header block
    - Week title, theme (2 sentences), time budget, end-of-week deliverable.

2. Table of Contents (anchored links to each day + cheatsheet + checklist).

3. ONE section per study day, in plan order. Each day section contains:

   a) Time budget line.
   b) Part A — Theory / Internals (when applicable):
      - Intuition (why this concept exists / what problem it solves).
      - Mechanics (how it actually works under the hood — go DEEP).
      - Complexity / cost model with concrete numbers.
      - JVM / Java-specific traps a Staff candidate must know.
      - Reference links (Oracle docs, JEPs, Effective Java items, Baeldung,
        original papers, engineering blogs).
   c) Part B — Problems. For EACH problem:
      - Title + LeetCode / NeetCode URL.
      - Statement (paraphrased, not copy-pasted).
      - Brute-force approach (always show this first — Staff candidates
        explain progression, not just the optimal answer).
      - Optimal approach with full Java code (idiomatic, modern Java 21).
      - Walk-through with a concrete small example.
      - Complexity analysis (time AND space, justified).
      - Edge cases (≥3 per problem).
      - **Trade-off drill** (REQUIRED): 2–3 framed questions of the form
        "When would you use approach A vs B?" — answers using the 3-axis
        template ("There are three things I'd think about: X, Y, Z…").
      - **Scale-up addendum** (REQUIRED): "What changes if the input is a
        stream? Doesn't fit in memory? Is sharded across machines?" —
        1 paragraph minimum.
      - **Junior-mistake callouts** (REQUIRED): "What a Senior says wrong
        that a Staff says right." 2–3 bullets.
      - Interview communication notes (how to verbalize the approach).
   d) Part C — Applied / Java deep dive (when the day has one).
   e) Internal-cross-references using [[anchor]] links to other days.

4. Mid-week or end-of-week REVIEW DAY:
    - Re-do protocol with target times.
    - Behavioral block (story bank progress — track running total).
    - Reflection prompts (5 questions, identical every week for consistency).
    - Tracker table row.

5. Week Cheatsheet (consolidated):
    - Patterns recognized this week + signal phrase that maps problem→pattern.
    - Idioms / one-liners introduced.
    - Decision trees / framing templates.
    - 3-axis trade-off answers for the week's hot topics.

6. Week Checklist:
    - Knowledge ("can you explain on a whiteboard"):  ~7–10 items.
    - Problems (with target time per problem):       all week's problems.
    - Behavioral (running totals).
    - Architecture judgment (blogs read this week).
    - Reflection (filled tracker, identified next-week change).

7. Consolidated reference link list at the end.
